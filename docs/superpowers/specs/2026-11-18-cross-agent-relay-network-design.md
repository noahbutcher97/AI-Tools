# Cross-agent relay across machines

Proposed on 2026-11-18 for owner review.

This extends the [cross-agent relay design](2026-08-23-cross-agent-relay-design.md), especially §4.1–4.6, §5–6, and Units 1–3. The relay gives Claude Code and Codex sessions the same way to find, address, wake, and check on a live session in any workspace or outside a project. CLI and MCP calls share one implementation. A doorbell carries data, and the receiving session gets its authority from an owner-approved source it already trusts. Delivery, a signature, and a named role leave that authority unchanged.

## Current implementation

At `9b14f51`, the CLI exposes `list` and `send`. MCP exposes `relay_list` and `relay_send`. Discovery is machine-local and defaults to workspace-tree scope. Codex delivery uses `codex queue`. Claude Code delivery uses the Unit 3 `claude -p` delegate, automatic through MCP and explicit with `--via-delegate` on the CLI. The current delegate uses `--permission-mode bypassPermissions`, `--tools SendMessage`, and `--strict-mcp-config`, with the prompt on stdin and the data inside nonce-delimited markers. Queue confirmation and delegate confirmation are transport receipts. The owner reports successful delivery on both providers and both desktops using the existing local routes.

Transcript content has two permitted uses. A dedicated proof reader returns receipt metadata only. The reference reader for `--re` returns up to 280 characters from the explicitly referenced turn in the exact destination session. Carry the excerpt as escaped quotation data, including across compaction. Preserve conversation and message ID correlation. The relay never interprets transcript text as an action. Retire general read and summary exports with their corresponding tests. Preserve and extend reference tests for wrong thread, bounded length, missing turn and forged markers. Remote receive accepts a typed turn ID on an authorized send only and returns no excerpt to the caller. Discovery uses registries and indexes. Before removing rollout-content discovery, count affected live threads with missing indexes or null source and report the change to workspace visibility and eligibility. Use filename and lock metadata for degraded inventory with unknown fields.

## 4.15 Addresses and discovery

| Selector | Meaning |
| --- | --- |
| `<id>` | Exact local provider session ID. This is the primary address. |
| `<host>:<id>` | Exact session ID on one canonical host. The local host prefix works the same way. |
| `<namespace>/<name>` | Optional live registration, resolved under §4.11. |
| `<host>:<namespace>/<name>` | Optional live registration limited to one host. |

Parse structured host and namespace selectors first. Reserve colon and slash in the new grammar. Use the raw ID for legacy names containing either delimiter. Reject empty components, option-shaped labels and ambiguous matches. Exact IDs take precedence over local legacy Claude session names. Keep the local legacy name form for compatible inputs, with explicit ambiguity errors. Recheck liveness and addressability on the destination immediately before dispatch. Codex uses the exact thread ID. For Claude, an exact raw ID resolves to the provider’s current delivery name, and the adapter checks that the name uniquely identifies that same live instance. Qualify stable native ID delivery if the provider supports it. If the provider only accepts names, the final registry check and the native call have a race during name reassignment. Pin that limitation with a controlled live test and document the measured behavior before claiming exact-session delivery. Ping always checks the original ID.

`list` preserves local scope and `--scope all`. `list --all-hosts` uses fleet-wide scope so it can discover sessions independently of checkout layout. An explicit `--scope cwd` applies the existing path filter only to local rows. Fleet-wide project filtering uses namespaces once available. `relay_list` accepts `all_hosts` and `relay_send` accepts the same selectors as CLI send. Both retain structured results. Remote projections include canonical host, ID, provider, addressability, and available state timestamps. Folder and other contextual fields cross the host boundary only when explicitly shared. Use placeholders such as `host-a:<id>` in public material.

`send` preserves stdin, `--message`, and `--dry-run`. The CLI still requires `--via-delegate` for Claude delivery. MCP grants the delegate path on either host. The destination independently enforces its installed policy. Dry-run gets a current resolution and eligibility result, performs zero provider delivery calls, and leaves the spool and receipt store untouched. It does not establish that a provider will accept a future send.

| Operation | CLI | MCP |
| --- | --- | --- |
| Discover and send | `list`, `send` | `relay_list`, `relay_send` |
| Prove delivery or check reachability | `ping <target>`, `ping --status <probe-id>`, `ping --all-hosts` | `relay_ping` with one of target, probe handle, or fleet reachability mode |
| Inspect readiness | `doctor`, `doctor --all-hosts` | `relay_doctor` with optional fleet scope |
| Register or inspect a session | `register`, `unregister`, `who` | `relay_register`, `relay_unregister`, `relay_who` |
| Subscribe and manage own subscriptions | `watch` | `relay_watch` with typed subscription operations |

The MCP schemas expose selectors, scope, and typed operands. Annotate fleet-capable tools as open-world and tools that wake sessions or write durable state as side-effecting. Keep `run` and the live doctor smoke probe on the CLI.

## 4.8 Host directory and restricted transport

### Directory and fleet queries

A starts with one owner-managed hosts file copied to every host. The same file maps canonical names to the settings needed to find each pinned SSH endpoint. A separate machine-local setting selects its own entry. H adds a directory adapter for bounded, read-only `tailscale status --json` calls. The adapter selects the configured tag, such as `tag:agent-host`, and maps each discovered DNS name privately to its unique short machine label (by default its normalized first component). Publish only the short label. The local host uses the same naming scheme. Validate duplicate names, conflicting local identity, and invalid entries before routing. In H, use the file when Tailscale is absent or unconfigured. If a configured Tailscale query fails, report degraded coverage and mark fallback status unknown. A successful query with an empty eligible set stays empty. Directory membership and the Tailscale `Online` flag describe discovery and mesh presence. A successful restricted receive probe establishes relay reachability.

`list`, `who`, and `doctor` accept `--all-hosts`. `ping --all-hosts` is a reachability sweep, reports `delivery: not_attempted`, and wakes zero sessions. `ping <target>` proves delivery to one live session. Fleet queries take one directory snapshot and start one direct request per member in parallel under a shared short deadline, initially three seconds. Document and validate the supported fleet size so no host silently falls outside the probe. Processes that cannot finish are cancelled. Return one row per member, including offline, timeout, identity mismatch, protocol mismatch, or degraded status, alongside successful rows. Results report completeness, and an incomplete result has a distinct CLI exit status. Unknown or last-known state carries its observation time. A single-target send or delivery ping has its own bounded provider deadline.

### Restricted receive

The initial Windows inventory client reads two private UTF-8 JSON files from the protected `CrossAgentRelay` installation directory under Program Files. `machine.json` selects the local label, for example `{"host":"host-a"}`. The shared `hosts.json` is an array with one entry per machine, for example `{"host":"host-b","endpoint":"host-b","port":22,"user":"operator"}`. Include the local entry. Provision SSH server pins in the adjacent `known_hosts` under those labels and select the machine's dedicated SSH identity from its private relay state. The receiver's peer label comes from the installed key restriction.

Use the platform SSH client in batch mode with a relay-owned client configuration, a pinned host key, explicit relay credential selection, and a fixed remote command, `relay receive`. Resolve the destination from the directory before spawning. Send one versioned, length-bounded UTF-8 JSON request on stdin. Only a fixed executable, fixed options, validated destination, and the literal receive command reach SSH argv. On the server the dedicated forced entrypoint launches the installed receiver with a fixed executable, working directory, and environment. It rejects other original commands and subsystems. Disable interactive shells, PTYs, agent and port forwarding, and arbitrary environment injection for the relay credential. Disable ambient proxies and agent fallback in the relay client configuration. The receiver runs against the intended owner profile and tests must prove that interactive sessions are discoverable from that SSH login. Keep the relay credential and its authorized entries distinct from ordinary administration.

The receive protocol dispatches locally, once, to strict schemas for inventory, reachability, resolve, send, ping start/status, and readiness. Later phases add narrow registry and session-state projections. The allowlist contains no command execution, remote subscriptions or registration, provider option overrides, arbitrary paths or file queries, spool reads, configuration edits, recursive fan-out, or credential operations. Each frame has a request ID and operation version. Bound inputs, output, and runtime, reject unknown fields and trailing frames, and return a structured reply with the request ID and responding host. Budget the rendered provider envelope as well as the wire frame, including Windows argv encoding for `codex queue`. Use explicit errors for oversize messages and mark an inventory partial if it hits a bound. Keep local diagnostics in protected state. Resolve selectors into local IDs before provider calls. On both local and remote paths, treat every display field as untrusted structured data, escaping controls in human output and keeping untrusted strings out of relay-authored prompt instructions.

**Authority on the receiving machine.** Treat processes with the owner's full account rights as one principal. They can use that machine’s SSH credential to call enabled receivers throughout its permitted fleet, forge local session metadata, and change any owner-writable configuration. An owner-only file does not isolate agents from each other. Protect executable paths, host pins, receive policy, watcher grants, and trust revisions under a separate administrative principal. Default remote bypass-class delivery to denied. Require an explicit grant for the transport-authenticated peer, destination, operation and origin provider. A provider-specific grant requires credible provider evidence from a protected broker. Before such evidence exists, only an explicit grant accepting unknown provider provenance can match. An inbound-disable switch overrides grants. Audit inbound peer, request ID, operation, disposition and time locally with bounded retention, excluding bodies and credentials. Dry-run audit may use aggregate counters outside its side-effect-free dispatch path.

**Headers and replies.** Use a dedicated remote sender branch in RELAY-META v2. A records the peer from the key-bound forced launcher, session provenance as claimed, and message signature as absent. D can add signed host attestation. Never pass remote evidence as local identity or resolve a remote sender against local names. Emit a structured reply target containing the authenticated short host label and a validated raw ID. Negotiate host-selector and envelope versions before sending. An older reader treats a v2 reply target as unsupported and never falls back to local resolution. Remove generated shell recipes. Validate IDs, kinds and correlation fields on CLI, MCP and receive. Put display strings, provider destination operands, claims and excerpts in escaped structured data. Keep instructions constant. All consequential actions require the recipient’s independent lookup of a pre-authorized local record.

**Request recovery from A.** Mint a caller-visible handle before submission and allow caller retries with the same request ID. Atomically reserve (authenticated peer, request ID) with the canonical request digest before dispatch. Return the recorded outcome on an identical retry and reject a changed digest. After possible submission, return unknown and direct the caller to `ping --status <handle>` without resending. Ordinary send status reports dispatch evidence only unless a proof cursor was captured. Receiver options come exclusively from a strict wire schema and receiver policy. Disable destination spooling, project bounded response fields and keep raw provider errors local. Initiator-only spooling requires a private directory and exclusive safe file creation with owner-only ACLs or mode 0600. If that fails, report spool unavailable. Prohibit predictable shared-temp fallback.

## 4.9 Delivery proof and readiness

The initial v2 send implementation supports remote Codex queue submission. The sender first resolves the raw ID without sharing the body. A compatible receiver checks the installed policy, the provider image and current addressability. The caller can supply a UUIDv7 with `--request-id` or MCP `request_id`. Following dispatch, `ping --status <host>:<request-id>` and MCP `relay_ping` with `status` query a peer-scoped receipt. A queued receipt establishes submission. The restricted Claude route requires the provider qualification below.

The Windows receiver expects `provider/codex.exe`, `receive-policy.json` and a setup-initialized `receipts.sqlite` in its protected installation directory. A private policy can grant a peer specific raw Codex IDs or all eligible Codex IDs using `{"enabled":true,"codex":[{"peer":"host-a","ids":"all"}]}`. Missing or invalid policy denies delivery. Receipt reservations preserve the request digest and state without retaining the message. A full or unavailable store refuses new submissions. Setup must preserve this store across upgrades. The provider image, store and grants require installation and live qualification on each receiving desktop.

### Ping

`ping <target>` takes a pre-send cursor on the target’s supported provider transcript, then issues one relay-generated notice with an unpredictable nonce and message ID. The destination keeps a durable receipt keyed by probe ID and bound to the exact target ID and instance, transcript cursor, and expected rendered bytes. A bounded polling window checks only new inbound records of the relevant provider shape. A probe wakes the recipient, may cost a turn, and says no reply is needed. Codex requires a consumed `userMessage` in `thread_items` after the cursor for that thread. Match its decoded text against the expected envelope, including the fresh nonce, relay message ID and exact body. Keep the queue confirmation ID as dispatch evidence. Include a positive test where the transcript `clientId` differs from that ID and negative tests for a copied body with the wrong nonce or message ID. A queued row is pending. For Claude qualify the receiver’s accepted inbound-message record using exact bytes and delivery metadata. Exercise prompting-mode held and released messages and bypass recipients. If the provider cannot distinguish a held message, return proof unavailable. Establish each predicate using a controlled live delivery before relying on it. A marker in assistant output, a tool result, a sender transcript, a sidechain, the wrong target, or a record predating the cursor cannot prove delivery.

Use read-only provider stores resolved locally within trusted roots. Read only the bounded records required to compare a specific probe. Handle partial records, rotation, cursor loss, unresolved target identity, unreadable data, and provider format drift as proof unavailable when they prevent verification. Only probe ID, target, timestamps, and a proof state leave the host. Valid states include `delivered`, `pending`, `proof_unavailable`, and `dispatch_failed`. A busy target can remain pending after the short interactive wait. `ping --status <probe-id>` looks up the existing receipt on the same host using the saved probe handle without sending again. Retain the target-bound cursor, nonce and expected digest in an authenticated probe handle so status can re-derive proof after a long turn or receipt expiry, subject to the same bounded reads. Expired or missing evidence yields unknown. CLI delivery probes to Claude use the same delegate opt-in as send. Proof means the doorbell landed in the transcript, with recipient response and execution outside that claim.

The CLI and MCP now expose target probes. A local probe seals its exact pre-send cursor and expected payload digest into an authenticated, encrypted status handle using an owner-private key. A remote Codex probe stores its cursor and digest alongside the peer-bound receipt. Status checks use bounded reads and never wake the target. In live CLI checks the local Codex probe advanced from pending to delivered. A Claude delegate reported acceptance while its prompting-mode recipient displayed a held message. The receipt remained pending until the single-message approval, then advanced to delivered without a second send.

### Doctor

`doctor --json` refreshes the owner-private readiness record. The MCP tool reads the dated record. `doctor --all-hosts` also queries the configured peers and writes a separate fleet record. The implementation compares the loaded build, directory revision, record age and peer clock. File presence is one setup observation. The installation acceptance checks below establish the effective SSH restrictions. For a live smoke probe, put the disposable Claude session's raw ID in the protected installation's `doctor-target.json` as `{"claude":"<id>"}` and invoke `doctor --probe-target <id>`. Unattended status checks use the last probe's evidence.

`doctor` checks the loaded relay build and receive protocol, provider executable resolution, sign-in, expiry where directly observable, delegate launch readiness, host directory, SSH restrictions where verifiable, and provider discovery. Compare a build fingerprint from the loaded distribution with the peer fingerprints, since the MCP package version can remain constant across commits. Report source revision when available. Add watcher health and subscription metadata in I and capabilities in G. A dated owner-controlled live probe to a designated disposable local session exercises the exact confined delegate with transcript proof. Run it via `doctor --probe-target <id>`. Ordinary fleet doctor fetches bounded local checks and recent live-probe evidence without waking targets. Report launchability, provider auth, live delegate delivery, and evidence age separately.

Each local CLI doctor run atomically writes a versioned `readiness.json` under owner-only relay state. Fleet doctor records one result per host with `checkedAt`, `validUntil`, build and protocol versions, readiness status, and sanitized evidence codes. Provider sign-in records include `expiresAt` when a supported provider status source exposes an actual expiry, otherwise `null` with a reason. Run fixed non-interactive status commands with bounded output where supported. Parse and retain only the status fields needed. Distinguish an expired login, an unobservable expiry, an absent CLI, and a probe error. Credentials, raw provider output, transcripts, network endpoints, and project secrets stay out of these records. The read-only MCP doctor and network doctor RPC returns a sanitized view and performs no install, repair, account sign-in, or policy change. A remote readiness response cannot overwrite the local readiness file directly.

## 4.10 Watcher and command completion

Run one watcher per machine for the designated owner profile. Use the platform’s logon service mechanism with a single-instance policy and an OS-owned lifetime lock. Bind durable state to the owner profile, with atomic or transactional writes for subscriptions, observed cursors, pending events, and delivery attempts. Report the live process identity, heartbeat, loaded configuration revision, and subscription states in doctor. A stale heartbeat alone cannot authorize a second watcher. Stopping the logon service releases its lock and cancels outstanding probes. Subscription records can be created, inspected, paused, and removed locally without restarting agent sessions.

`watch --notify <target> <condition>` adds a local subscription under owner policy. The condition selects a typed, approved definition from private configuration or a job created by the caller. File and job watchers run on the machine owning the resource. The recipient can be local or remote. The private config maps projects to observation roots and condition IDs and authorizes notification targets. The CLI and planned MCP watch tool share the policy. A live session ID is a forgeable claim. The protected watcher broker issues a capability under an owner grant, binding allowed operations, condition or job, exact recipient instance and disclosure level. Treat mutually readable capabilities as account-level and require independent owner grants for sensitive observations. Other destinations, persistent name rebinding, and expanded metadata require an explicit grant. The watcher accepts no remote subscription mutation over SSH. Doctor reports subscription ID, condition type, timestamps, target binding state, and last outcome. Private paths, remote URLs, ref names, and log content stay out of the fleet readiness projection.

| Condition | Observation and confinement |
| --- | --- |
| Remote branch moves | Poll the configured remote ref through a fixed, qualified Git invocation with an approved endpoint, protocol, and ref. Isolate ambient repo config and helpers, block prompts, and use an owner-approved credential context. Emit a change only after a successful observation differs from its baseline. |
| File changes | Compare identity, size, and timestamps under approved local roots. Resolve and verify containment at access time, including Windows reparse points and path races. Watch bounded definitions and emit metadata only. A metadata poll may miss intermediate changes. |

### Local broker for completion reports

A protected launcher starts `completion-broker.mjs` with an installed runtime, code and environment. On Windows the broker checks its assigned account against the session account and refuses elevated startup. Administrators provision `completion-principals.json` with the two account SIDs, `completion-policy.json` with the approved provider, raw ID and instance bindings, and a separately protected `completion-state` directory containing the initialized job database. Setup owns this provisioning. Startup checks ownership, write access, private state read access and redirected files before listening. The policy authority must preserve these ACLs when replacing a file. The verifier is included in the relay build fingerprint.

The broker listens on local IPv4 loopback. A caller with a broker-issued job grant can claim the job once before launching a process under the caller’s rights. The claim is consumed even if its acknowledgement is lost. A wrapper that gets no authenticated claim acknowledgement must stop before launch. It reports only the resulting exit code or signal. Each request authenticates its operation, job, fresh nonce and exact outcome using a per-job MAC. The secret stays off the wire. The acknowledgement uses a separate MAC domain and follows the database commit. An identical completion can be acknowledged again after restart. ### CLI command launch

`relay run -- <executable> [args...]` accepts one pre-issued job grant on private stdin. With a terminal or empty stdin, the CLI can also use a batch issued for the local Claude instance or the local Codex thread. Malformed input fails immediately. Each grant contains a job ID and a bearer capability. Keep capabilities out of shell history, environment variables, transcripts, arguments and diagnostics. For Codex it contains exactly `id`, `provider` set to `codex`, and `scope` set to `thread-status`. This grant permits reporting only to that raw thread through the issuing machine’s local broker and queue. One batch holds one to eight grants. Setup assigns directory write access to the broker and installation authorities, and read access to the designated desktop user. Processes running as that user share the same access to its grants.

It checks grant availability with bounded authenticated queries. The broker rechecks the policy, session binding, expiry and unused state on the actual claim. Availability and completion frames carry no executable, arguments, log content or destination override.

The observer inherits the caller’s execution rights and working directory, passes the literal executable and argument vector directly to the OS, and gives the command closed input and discarded output. Provider policy must authorize the command in its launch context. Setup must qualify that context before making job grants available there. The CLI returns the job ID and `started` after the OS confirms process creation. A refusal or known failure returns `not_started`; loss of the startup acknowledgement returns `unknown` and must not trigger a replacement launch. A spawn failure after a successful claim records `start_failed`. The observer retries the same termination report with bounded backoff. If the observer is lost or exhausts those attempts, the broker has no confirmed outcome. Recording the outcome and proving delivery to a session are separate operations.

### Automatic completion notices

The broker’s completion watcher starts after it acquires the exclusive local listener and receives a trusted session-profile delivery adapter. The standalone broker accepts job reports with dispatch disabled until its launcher supplies that adapter. The dedicated broker account must never run a provider using its own credentials. On shutdown the watcher cancels the current adapter call and retains the listener until that call returns.

An accepted termination opens a 750 ms coalescing window. A pass selects the oldest due job and groups up to eight ready completions for the same machine-local provider, raw ID and instance. Individual exit codes or signals appear in the notice. A closed Codex thread with no addressable writer leaves the notice ready for a later check until grant expiry. Once the handle is reserved, the watcher checks only that handle. It marks delivery after the exact notice appears as a consumed user message in the original thread. Revocation blocks future submissions and proof checks. An already queued message can still arrive after revocation. No command, working directory, output or tail is included, and no other machine, name or thread can serve as a fallback. The watcher rechecks every grant and atomically reserves all members before submission. If any member loses authorization before the proof handle is saved, the whole attempt stops. Eligible members can be reconsidered on their next due pass.

Each member receives the same sealed proof handle in one transaction before the provider call. That transaction starts a ten-second cooldown for further notices to the same instance, including overflow and new arrivals. A restart checks the original handle and honors the cooldown. A crash before the handle is saved leaves the reservation uncertain. The scheduler persists its retry time before beginning work and backs off from two seconds to one minute within the grant lifetime. Jobs whose send outcome is uncertain never re-enter the send queue. Existing job stores upgrade in a transaction that retains states and handles.

## 4.11 Namespaces and registry

An optional registration is a lease keyed to the local provider and raw session ID, with a normalized `namespace/name` alias. A registration can carry role, reported provider and machine, folder, branch, head, current step, and a reported timestamp. The relay stamps its own observation time, canonical host, provider and ID from the locally resolved caller. It checks a live session match before allowing a caller to register, renew or remove its own record. Owner-approved administrative repair is local. Validate labels, field shapes, limits, and lease expiry. Store records outside repositories. Names use a documented case-insensitive grammar that forbids separators inside each component and preserves the raw address grammar. Workspace association remains optional.

`who` joins observed live inventory with current leases by canonical host, provider, and raw ID. Observed busy/idle status, last activity, and supported turn counters come from each provider adapter, with an unknown state when the source cannot establish them. Other values are self-reported, attributed and time-stamped. A claimed machine or provider cannot override routing. Report unregistered sessions by ID, expired records as stale where useful, and duplicate live claims explicitly. An observer may see several differently named sessions with the same role.

Resolve an unqualified alias only from a complete snapshot with one live claimant. A host-qualified alias requires a unique claim on that host. For each attempt, pin the resolved host, provider, ID, and lease revision. Revalidate the exact lease and session immediately before sending. Concurrent registrations on different hosts can race a federated snapshot. Pinning the destination prevents an already resolved send from switching to another claimant, and subsequent snapshots report the collision. This design gives snapshot uniqueness rather than a globally exclusive name lease. Require atomic host-local name exclusivity at registration and owner-assigned machine, provider and workspace constraints before enabling a watch to follow that name. Raw ID delivery requires no registry call, lease, workspace, or fleet-wide availability.

## 4.14 Signed cross-host envelopes

D adds a distinct Ed25519 signing key per machine. Use a policy-enforcing signer under a separate principal with an agent-inaccessible key. Owner-readable keys can only establish account-level provenance. A synced trusted-machines file binds canonical names and key IDs to public keys and allowed validity windows. Sender and receiver authenticate signed requests and replies with independent signing domains. Sign a canonical, versioned encoding covering the operation, request ID, source host, destination host, created and expiry timestamps, nonce, and all payload bytes including sender evidence and body. A reply signs its request binding and result. Canonical encoding and field validation reject duplicate keys, unsupported encodings or versions, unknown fields, and ambiguous values before verification. No key, trust entry, host, or algorithm supplied by a request can override local trust policy.

Check the signature, destination, expiration, acceptable clock skew, and sender/key mapping before provider dispatch. Reserve each authenticated source and request ID in a durable, bounded replay store before any effect. A duplicate may retrieve a known receipt through the permitted status path and cannot dispatch twice. A crashed in-progress request remains uncertain through its validity window. Rotate by distributing trusted public keys first, supporting a bounded overlap, then retiring the old key. In signed mode, invalid and unsigned frames fail closed, including after transport retries. Mixed-version rollout reports protocol incompatibility or explicitly configured unsigned mode with an unverified origin.

Report machine signature and session evidence independently. A valid signature shows that a trusted machine key vouched for exactly those bytes. A session attribution must also come from that machine’s normal CLI/MCP identity mechanism, checked against live discovery and carried as host-attested evidence. A machine can misstate its own session observations, and the existing same-account launch limitation applies. Render key ID and evidence in the relay-generated header with the host-qualified reply address. The destination builds the body wrapper after verification and signs its receipt separately. Keep signing keys and replay state out of both provider tool inputs and transcript proof output.
